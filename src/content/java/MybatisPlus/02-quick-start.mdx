# 第 2 节：入门案例与完整建项

本节的最终结果：在 `mp-demo` 中运行 `UserMapperTest`，看到 MP 生成的 SQL，并完成按 ID 查询、批量查询、新增、修改、删除。视频里先导入现成工程与 `mp.sql`，随后用 MP Starter 替换 MyBatis Starter；下面也写全没有素材时从零复现的步骤。

## 0. 准备与项目结构

准备 **JDK 11、Maven、IntelliJ IDEA、MySQL 8**。先用终端检查 `java -version`、`mvn -version`、`mysql --version`；IDEA 的 **Project SDK**、Maven Importer 的 JDK 也要指向 JDK 11。将项目放在没有空格和特殊字符的目录，例如 `D:/code/mp-demo`。

最终结构如下；包名与文件位置直接影响 Spring Boot 组件扫描和测试启动：

```text
mp-demo/
├─ pom.xml
└─ src/
   ├─ main/
   │  ├─ java/com/itheima/mp/
   │  │  ├─ MpDemoApplication.java
   │  │  ├─ domain/po/User.java
   │  │  └─ mapper/UserMapper.java
   │  └─ resources/application.yaml
   └─ test/java/com/itheima/mp/mapper/UserMapperTest.java
```

### 课程已有素材时

将课前的 `mp-demo` 拷贝到工作目录，用 IDEA 打开 `pom.xml` 所在目录；在 IDEA 的 **File → Project Structure** 选 JDK 11；用数据库工具执行课前的 `mp.sql`；最后修改 `application.yaml` 的数据库账号与密码。之后直接跳到“第 4 步：替换依赖”。**不要对已有练习库重复执行下文的重建 SQL**。

### 没有课程素材时

按以下第 1–7 步做。创建工程和建表 SQL 是本笔记的可复现补全；业务字段、四条用户初始数据及案例包名与课堂画面保持一致。本节先操作 `user`；第 3、4 节将用 `tb_user` 演示注解与配置；`address` 是配套工程的后续练习准备。

## 1. 创建 Maven 工程

在 IDEA 选择 **New Project → Spring Initializr**：Name/Artifact 填 `mp-demo`，Group 填 `com.itheima.mp`，Language 选 Java，Build 选 Maven，JDK 选 11，Spring Boot 选 **2.7.12**。若初始化器不再提供这个旧版本，创建普通 Maven 工程后直接把 `pom.xml` 替换为下方内容即可。先选 `Spring Boot Starter`、`MySQL Driver`、`Lombok`、`Spring Boot Starter Test`；MP 依赖在第 4 步加入。

## 2. 建库、建表、导入初始数据

## 3. 配置数据库连接

在 `src/main/resources/application.yaml` 写入以下内容。将用户名和密码替换成**你的练习数据库**凭据；不要照抄课程截图中的密码。日志级别用于观察生成的 SQL。

```yaml
spring:
  datasource:
    url: jdbc:mysql://127.0.0.1:3306/mp?useUnicode=true&characterEncoding=UTF-8&serverTimezone=Asia/Shanghai
    driver-class-name: com.mysql.cj.jdbc.Driver
    username: root
    password: 你的MySQL密码
logging:
  level:
    com.itheima: debug
  pattern:
    dateformat: HH:mm:ss
```

验收点：MySQL 服务已启动；库名是 `mp`；数据库连接能在 IDEA 中测试成功。若本机 MySQL 端口不是 `3306`，只改 URL 中的端口。

## 4. 写启动类与实体

如果从零建项，确认 POM 已包含上文的 MP Starter；若使用课程给的旧工程，则在 `pom.xml` 加入 `mybatis-plus-boot-starter:3.5.3.1`，并移除原来的 MyBatis Starter，然后重新加载 Maven。MP Starter 会负责 MyBatis 与 MP 的自动装配。

`src/main/java/com/itheima/mp/MpDemoApplication.java`：

```java

import org.springframework.boot.SpringApplication;
import org.springframework.boot.autoconfigure.SpringBootApplication;

@SpringBootApplication
public class MpDemoApplication {
    public static void main(String[] args) {
        SpringApplication.run(MpDemoApplication.class, args);
    }
}
```

`src/main/java/com/itheima/mp/domain/po/User.java`：

```java
package com.itheima.mp.domain.po;

import lombok.Data;
import java.time.LocalDateTime;

@Data
public class User {
    private Long id;
    private String username;
    private String password;
    private String phone;
    private String info;
    private Integer status;
    private Integer balance;
    private LocalDateTime createTime;
    private LocalDateTime updateTime;
}
```

此时实体没有 MP 注解也可以工作：类名 `User` 对应 `user` 表，`id` 是主键，`createTime`/`updateTime` 按驼峰转下划线映射。`@Data` 是 Lombok 注解，用于生成 getter/setter；若 IDEA 中调用 `setUsername` 报红，检查 Lombok 依赖及注解处理是否开启。

## 5. 定义 Mapper

`src/main/java/com/itheima/mp/mapper/UserMapper.java`：

```java
package com.itheima.mp.mapper;

import com.baomidou.mybatisplus.core.mapper.BaseMapper;
import com.itheima.mp.domain.po.User;
import org.apache.ibatis.annotations.Mapper;

@Mapper
public interface UserMapper extends BaseMapper<User> {
}
```

关键是 `extends BaseMapper<User>`：`BaseMapper` 提供通用单表方法，`User` 让 MP 能找到实体映射。这里用 `@Mapper` 把接口注册为 Spring Bean；也可改为在启动类上用 `@MapperScan("com.itheima.mp.mapper")` 批量扫描，二者选一种即可。

## 6. 编写并运行测试

`src/test/java/com/itheima/mp/mapper/UserMapperTest.java`：

```java
package com.itheima.mp.mapper;

import com.itheima.mp.domain.po.User;
import org.junit.jupiter.api.Test;
import org.springframework.beans.factory.annotation.Autowired;
import org.springframework.boot.test.context.SpringBootTest;

import java.time.LocalDateTime;
import java.util.List;

@SpringBootTest
class UserMapperTest {
    @Autowired
    private UserMapper userMapper;

    @Test
    void testSelectById() {
        User user = userMapper.selectById(1L);
        System.out.println("user = " + user);
    }

    @Test
    void testSelectByIds() {
        List<User> users = userMapper.selectBatchIds(List.of(1L, 2L, 3L, 4L));
        users.forEach(System.out::println);
    }

    @Test
    void testInsert() {
        User user = new User();
        user.setId(5L);
        user.setUsername("Lucy");
        user.setPassword("123");
        user.setPhone("18688990011");
        user.setBalance(200);
        user.setInfo("{\"age\":24,\"intro\":\"英文老师\",\"gender\":\"female\"}");
        user.setCreateTime(LocalDateTime.now());
        user.setUpdateTime(LocalDateTime.now());
        userMapper.insert(user);
    }

    @Test
    void testUpdateById() {
        User user = new User();
        user.setId(5L);
        user.setBalance(20000);
        userMapper.updateById(user);
    }

    @Test
    void testDelete() {
        userMapper.deleteById(5L);
    }
}
```

**不要一次运行整个测试类。** 测试会改动数据库，执行顺序也不由方法排列保证。按 `testSelectById` → `testSelectByIds` → `testInsert` → 将查询方法的 ID 暂改为 `5L` 运行 → `testUpdateById` → 再查 `5L` → `testDelete` 的顺序，逐个点 IDEA 的绿色运行按钮。也可以用 `mvn '-Dtest=UserMapperTest#testSelectById' test` 单独执行查询测试。

每一步的验收点：

| 步骤 | 数据库与控制台应看到什么 |
| --- | --- |
| 查 ID 1 | 返回 `Jack`；SQL 带 `WHERE id=?` |
| 查 ID 1–4 | 返回四名用户；SQL 带 `IN (...)` |
| 新增 ID 5 | `Lucy` 被插入；`SELECT * FROM user WHERE id=5` 可查到 |
| 更新 ID 5 | `balance` 变为 `20000`；其他非空字段保留 |
| 删除 ID 5 | 只删除练习记录；ID 1–4 仍在 |

日志中应有类似 `Preparing: SELECT id,username,...,create_time,update_time FROM user WHERE id=?` 以及 `Parameters: 1(Long)`。这证明 SQL 由 MP 生成并交给 MyBatis 执行；打印了 SQL 但查不到记录时，先核对连接的库和 ID。

## 7. 常见卡点与本节收束

- `No qualifying bean of type UserMapper`：`@Mapper` 漏了，或启动类不在 `com.itheima.mp` 的上层包。
- `Table 'mp.user' doesn't exist`：SQL 没导入 `mp` 库，或 URL 指到了其他库。
- `Unknown column 'create_time'`：实体字段与库表不一致；检查建表 SQL 和下一节的映射规则。
- `Duplicate entry '5'`：已运行过新增；先检查 `SELECT id,username FROM user WHERE id=5`，只在确认是本练习数据时删除它，再重新运行。
- `Data truncation: Cannot create a JSON value`：`info` 必须是合法 JSON 字符串。
- `Unsupported class file major version`：Project SDK、Maven 使用的 JDK 和 POM 的 `java.version` 不一致。

到这里，你应能解释本节的最短流程：**连库 → 引入 MP Starter → 实体映射 → Mapper 继承 `BaseMapper<User>` 并被扫描 → 在测试中调用 CRUD → 观察 SQL 和库表变化。**
