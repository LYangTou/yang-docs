# 第 1 节：MyBatis-Plus 介绍

## 先回答：为什么要学它

在已有 MyBatis 项目中，用户表等单表的新增、按主键查询、修改和删除通常需要一组结构相似的 SQL 与 Mapper 方法。业务逻辑不复杂，但每张表都重复写一遍，维护成本会随表的数量增加。

MyBatis-Plus（简称 MP）是 MyBatis 的增强工具。它通过通用 Mapper 等能力提供单表 CRUD，减少重复代码；原有 MyBatis 自定义 SQL 的能力仍可使用。课程前四节的主线就是：**为现有 Spring Boot + MyBatis 风格工程引入 MP，让 `UserMapper` 继承 `BaseMapper<User>`，再理解它怎样把 `User` 映射到数据库的 `user` 表。**

## 课堂上的知识关系

```text
Spring Boot 工程 + MySQL 数据源
              ↓
引入 MyBatis-Plus Starter（自动装配）
              ↓
UserMapper extends BaseMapper<User>
              ↓
MP 从 User 实体推断表、主键和列
              ↓
生成并执行常见的单表 CRUD SQL
```

`BaseMapper<T>` 的泛型 `T` 不是装饰：它告诉 MP 这个 Mapper 操作哪个实体。实体和数据库命名不一致时，再用注解或全局配置明确映射规则。复杂或特殊 SQL 可以继续写在 Mapper XML 中，第四节会演示。

## 本节要建立的判断

- **适用处**：重复度高的单表 CRUD；例如按 ID 查询用户、更新用户余额。
- **本节前置知识**：Java、Maven、Spring Boot、MyBatis 的 Mapper 与数据库连接。
- **不要误解**：引入依赖后并非任意实体都自动正确映射。表名、主键、字段名与默认规则不符时，必须显式声明。
- **学习目标**：先掌握一次完整的 CRUD 路径，再学习常用注解与配置，后续才进入条件构造器等功能。

## 口头检查

如果只需“根据用户 ID 查一条记录”，传统做法通常要声明方法并提供 SQL；使用 MP 时可以直接调用 `userMapper.selectById(id)`。请说出这行代码执行之前必须具备的三项信息：**可用的数据源、被扫描到的 Mapper、正确的实体与表映射**。
