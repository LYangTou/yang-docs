# Java 静态代理与动态代理学习笔记

## 1. 项目示例概览

本模块围绕 `MathCalculator` 展示代理模式：

```java
public interface MathCalculator {
    int add(int i, int j);
    int sub(int i, int j);
    int mul(int i, int j);
    int div(int i, int j);
}
```

`MathCalculatorImpl` 是真实业务对象，也叫目标对象（target）。代理对象不改变目标对象的核心计算逻辑，而是在调用前后插入日志、权限、事务、耗时统计等横切逻辑。

```text
调用方 → 代理对象 → 目标对象
          └─ 附加逻辑
```

代理的核心思想是：调用方依赖接口，而不是依赖具体实现类。项目中的测试也体现了依赖倒置：

```java
MathCalculator calculator = ...;
calculator.add(1, 2);
```

## 2. 静态代理

### 2.1 定义

静态代理是在编译期就写好代理类和目标对象之间的关系。代理类通常实现与目标对象相同的接口，并把目标对象保存为自己的成员变量。

项目中的 [CalculatorStaticProxy.java](src/main/java/com/example/springaop/proxy/statics/CalculatorStaticProxy.java) 就是静态代理：

```java
public class CalculatorStaticProxy implements MathCalculator {
    private MathCalculator target;

    public CalculatorStaticProxy(MathCalculator target) {
        this.target = target;
    }

    @Override
    public int add(int i, int j) {
        System.out.println("======== add ++++++======");
        return target.add(i, j);
    }
}
```

使用方式：

```java
MathCalculator target = new MathCalculatorImpl();
MathCalculator proxy = new CalculatorStaticProxy(target);
proxy.add(2, 3);
```

### 2.2 调用过程

调用 `proxy.add(2, 3)` 时：

1. 先进入 `CalculatorStaticProxy.add(...)`。
2. 代理执行额外逻辑，例如打印日志。
3. 代理调用内部保存的 `target.add(...)`。
4. 目标对象完成真正的加法并返回结果。
5. 代理把结果返回给调用方。

### 2.3 优点与缺点

优点：

- 结构直观，容易阅读和调试。
- 可以针对某个方法编写非常明确的增强逻辑。
- 不依赖反射，调用链和类型关系清晰。
- 同一个代理类可以包装多个实现了相同接口的目标对象。

缺点：

- 每个目标类型通常都要手写一个代理类。
- 代理类必须实现目标接口的全部方法。
- 接口新增方法时，静态代理也要同步修改，否则无法编译。
- 如果很多类都需要相同日志逻辑，会产生大量重复代码。

项目中的静态代理只在 `add` 方法中打印日志，其他方法只是简单转发，这正好体现了“手写、逐方法维护”的特点。

## 3. JDK 动态代理

### 3.1 定义

JDK 动态代理在运行时生成代理对象，不需要提前编写一个具体的代理实现类。项目中的 [DynamicProxy.java](src/main/java/com/example/springaop/proxy/dynamic/DynamicProxy.java) 使用了 JDK 原生的：

```java
Proxy.newProxyInstance(...)
```

JDK 动态代理有一个前提：目标对象必须实现至少一个接口。生成的代理对象也只能调用这些接口中声明的方法，不能直接代理目标类额外定义的普通方法。

### 3.2 三个核心参数

```java
Proxy.newProxyInstance(
    target.getClass().getClassLoader(),
    target.getClass().getInterfaces(),
    invocationHandler
);
```

1. `ClassLoader loader`：加载生成的代理类，通常使用目标对象的类加载器。
2. `Class<?>[] interfaces`：代理对象实现的接口列表，通常取目标对象实现的接口。
3. `InvocationHandler h`：统一处理代理方法调用的回调对象。

### 3.3 `InvocationHandler.invoke(...)`

```java
InvocationHandler handler = (proxy, method, args) -> {
    LogUtils.startLog(method.getName());
    Object result = method.invoke(target, args);
    LogUtils.endLog(method.getName(), result);
    return result;
};
```

三个参数分别表示：

- `proxy`：当前生成的代理对象。
- `method`：调用方准备执行的接口方法。
- `args`：调用方传入的参数；无参数方法时可能为 `null`。

代理对象的每一次接口方法调用，都会进入 `invoke(...)`。因此可以在目标方法调用前后统一织入逻辑：

```text
invoke 开始
→ 记录开始日志
→ 修改或校验参数（可选）
→ method.invoke(target, args)
→ 记录返回值或异常
→ 返回结果
```

项目中的 `DynamicProxy.getProxyInstance(target)` 将这套流程封装起来：

```java
MathCalculator proxy = (MathCalculator)
        DynamicProxy.getProxyInstance(new MathCalculatorImpl());

proxy.div(10, 0);
```

### 3.4 动态修改参数

在 `invoke(...)` 中可以修改 `args`，目标方法将收到修改后的参数：

```java
args[1] = 4;
return method.invoke(target, args);
```

这说明动态代理不仅可以记录日志，也可以在调用目标对象前进行参数校验、参数转换或权限判断。但业务上要谨慎修改调用方传入的数组，避免造成难以追踪的副作用。

### 3.5 异常处理

项目代码使用：

```java
try {
    result = method.invoke(target, args);
} catch (Exception e) {
    LogUtils.logException(method.getName(), e.getCause());
} finally {
    LogUtils.logReturn(method.getName(), result);
}
```

`Method.invoke(...)` 反射调用失败时，目标方法抛出的异常通常会被包装在 `InvocationTargetException` 中，真实异常可以通过 `getCause()` 获取。

当前示例记录异常后没有继续抛出，因此调用方可能拿到 `null` 或默认结果。这适合演示日志流程，但生产代码通常应记录后重新抛出，避免把业务失败伪装成成功。

## 4. 静态代理与 JDK 动态代理对比

| 对比项 | 静态代理 | JDK 动态代理 |
| --- | --- | --- |
| 代理类产生时间 | 编译前/编码时手写 | 运行时生成 |
| 代理关系 | 代码中固定 | 创建代理对象时决定 |
| 实现方式 | 手写同接口代理类 | `Proxy` + `InvocationHandler` |
| 是否依赖接口 | 通常实现同一接口 | 必须依赖接口 |
| 方法维护 | 每个方法手动转发 | 统一进入 `invoke` |
| 反射 | 不需要 | 使用 `Method.invoke` |
| 重复代码 | 较多 | 较少 |
| 调试难度 | 较低 | 需要理解反射调用链 |
| 目标类新增接口方法 | 代理类需要同步修改 | 通常由统一处理器接管 |
| 目标类没有接口 | 可以手写继承/组合代理 | JDK 代理不能直接代理 |

一句话记忆：静态代理是“提前写好一个代理类”，JDK 动态代理是“运行时根据接口和处理器生成代理对象”。

## 5. 当前项目与 Spring 的关系

### 5.1 当前代码的 Spring 装配现状

`CalculatorStaticProxy` 标有 `@Component`，但 `MathCalculatorImpl` 的 `@Component` 注解被注释/没有启用：

```java
public class MathCalculatorImpl implements MathCalculator {
```

静态代理的构造器需要一个 `MathCalculator`：

```java
public CalculatorStaticProxy(MathCalculator mc) {
    this.target = mc;
}
```

如果想让 Spring 自动装配这条链路，需要让目标对象先成为 Bean，例如：

```java
@Component
public class MathCalculatorImpl implements MathCalculator {
}
```

然后 Spring 才能创建：

```text
MathCalculatorImpl Bean → CalculatorStaticProxy Bean → @Autowired MathCalculator
```

如果同时存在多个 `MathCalculator` Bean，需要用 `@Qualifier` 或 `@Primary` 明确注入哪个对象。

### 5.2 `@Autowired MathCalculator` 注入什么

当静态代理和目标实现都同时注册为 `MathCalculator` 类型时，单纯按类型注入会有多个候选，可能产生 `NoUniqueBeanDefinitionException`。生产代码通常会：

- 只暴露代理 Bean；或
- 使用 `@Primary` 标记代理；或
- 使用 `@Qualifier` 指定目标和代理的名称。

Spring AOP 通常会自动创建代理对象，调用方仍然依赖业务接口，不需要手动 `new CalculatorStaticProxy(...)`。本模块当前主要演示 Java 原生代理机制，还没有写 `@Aspect`、切点和通知。

## 6. 容易混淆的概念

### 6.1 代理不是目标对象本身

代理和目标对象都可能实现 `MathCalculator`，但它们是两个不同的对象：

```java
proxy != target
```

调用方应该持有代理对象，才能看到增强逻辑；如果绕过代理直接调用目标对象，日志等增强就不会执行。

### 6.2 JDK 动态代理不是“代理万物”

源码注释中“可以代理万物”是便于理解的概括，但 JDK 动态代理有明确限制：目标对象必须有接口，且只能拦截接口方法。没有接口的类通常需要使用基于子类的代理方案，例如 CGLIB；本项目没有演示 CGLIB。

### 6.3 `InvocationHandler` 类似统一拦截器

它可以处理多个接口方法，但仍需决定：

- 什么时候调用目标方法。
- 是否修改参数。
- 如何处理返回值。
- 如何处理异常。
- 是否在 finally 中执行收尾逻辑。

如果忘记 `method.invoke(target, args)`，目标业务方法就不会执行；如果忘记返回结果，非 `void` 方法的调用方可能得到错误结果。

## 7. 复习与练习建议

1. 为静态代理的 `sub`、`mul`、`div` 也加入统一日志，体会接口变更带来的维护成本。
2. 在 JDK 动态代理中打印 `method.getName()`、参数和返回值。
3. 修改 `args` 后观察目标方法收到的实际参数。
4. 对 `div(10, 0)` 保留异常并重新抛出，比较吞掉异常前后的调用结果。
5. 给 `MathCalculatorImpl` 添加 `@Component`，再观察 Spring 如何创建目标对象和代理对象。
6. 后续学习 Spring AOP 时，把当前 `InvocationHandler` 中的“前置逻辑、目标调用、异常逻辑、返回逻辑”分别对应到通知类型。
