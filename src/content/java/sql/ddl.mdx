# MySQL DDL 基础：数据库、表与数据类型

> 关系型数据库以二维表组织数据，并通过表之间的关系描述业务。本文从 SQL 的基本规则和分类入手，重点介绍使用 DDL 管理数据库与表的方法。

## 先看结论

- SQL 语句通常以分号结尾，关键字不区分大小写，但建议使用大写以提高可读性。
- SQL 可分为 DDL、DML、DQL 和 DCL；本文重点介绍用于定义数据库对象的 DDL。
- 数据库层面的常用操作包括查看、创建、选择和删除数据库。
- 表结构设计需要同时考虑字段名称、数据类型、长度、约束和注释。
- `DELETE`、`TRUNCATE` 和 `DROP` 分别用于删除数据、清空表和删除表结构。

## 关系型数据库

关系型数据库建立在关系模型之上，通常由多张相互关联的二维表组成。一张表由行和列构成：

- 行表示一条记录，例如一名员工的信息。
- 列表示一个字段，例如姓名、年龄或入职日期。
- 表之间可以通过共同字段建立关系。

## SQL 通用语法

编写 MySQL SQL 语句时，需要注意以下规则：

1. SQL 语句可以写成一行或多行，通常以分号 `;` 结尾。
2. 可以使用空格和缩进提高语句的可读性。
3. MySQL 的 SQL 关键字不区分大小写，通常建议使用大写。
4. 表名和字段名是否区分大小写会受操作系统及 MySQL 配置影响，不应依赖大小写混用。

SQL 支持三种常见注释形式：

```sql
-- 单行注释，双横线后需要有空格
# MySQL 特有的单行注释
/* 多行注释 */
```

## SQL 分类

| 分类 | 全称 | 主要作用 | 常见关键字 |
| --- | --- | --- | --- |
| DDL | Data Definition Language | 定义数据库、表、字段等数据库对象 | `CREATE`、`ALTER`、`DROP`、`TRUNCATE` |
| DML | Data Manipulation Language | 新增、修改和删除表中的数据 | `INSERT`、`UPDATE`、`DELETE` |
| DQL | Data Query Language | 查询表中的数据 | `SELECT` |
| DCL | Data Control Language | 管理用户及访问权限 | `GRANT`、`REVOKE` |

## 数据库操作

DDL 可以创建、查看和删除数据库。执行表操作前，通常还需要选择当前使用的数据库。

### 查看数据库

```sql
-- 查看所有数据库
SHOW DATABASES;

-- 查看当前数据库
SELECT DATABASE();
```

### 创建数据库

```sql
CREATE DATABASE [IF NOT EXISTS] 数据库名
    [DEFAULT CHARACTER SET 字符集]
    [COLLATE 排序规则];
```

例如，创建使用 `utf8mb4` 字符集的数据库：

```sql
CREATE DATABASE IF NOT EXISTS company
    DEFAULT CHARACTER SET utf8mb4;
```

`IF NOT EXISTS` 可以避免数据库已经存在时直接报错。

### 选择数据库

```sql
USE company;
```

选择数据库后，未显式指定数据库名的表操作默认在当前数据库中执行。

### 删除数据库

```sql
DROP DATABASE IF EXISTS company;
```

删除数据库会同时删除其中的表和数据，执行前应确认目标名称并做好备份。

## 表结构查询

```sql
-- 查看当前数据库中的所有表
SHOW TABLES;

-- 查看表的字段结构
DESC employee;

-- 查看完整建表语句
SHOW CREATE TABLE employee;
```

`DESC` 适合快速查看字段、类型和键信息，`SHOW CREATE TABLE` 则能看到字符集、存储引擎和约束等完整定义。

## 创建表

基本语法如下：

```sql
CREATE TABLE 表名 (
    字段1 数据类型 [COMMENT '字段注释'] [约束],
    字段2 数据类型 [COMMENT '字段注释'] [约束],
    ...
    字段n 数据类型 [COMMENT '字段注释'] [约束]
) [COMMENT '表注释'];
```

例如，创建员工表：

```sql
CREATE TABLE employee (
    id        INT              COMMENT '编号',
    workno    VARCHAR(10)      COMMENT '工号',
    name      VARCHAR(20)      COMMENT '姓名',
    gender    CHAR(1)          COMMENT '性别',
    age       TINYINT UNSIGNED COMMENT '年龄',
    idcard    CHAR(18)         COMMENT '身份证号',
    entrydate DATE             COMMENT '入职时间'
) COMMENT '员工表';
```

## MySQL 常用数据类型

选择数据类型时，应在业务表达能力、存储空间和计算精度之间取得平衡。

### 数值类型

| 类型 | 存储空间 | 有符号范围 | 无符号范围 | 典型用途 |
| --- | ---: | --- | --- | --- |
| `TINYINT` | 1 字节 | -128～127 | 0～255 | 年龄、状态值 |
| `SMALLINT` | 2 字节 | -32,768～32,767 | 0～65,535 | 较小整数 |
| `MEDIUMINT` | 3 字节 | -8,388,608～8,388,607 | 0～16,777,215 | 中等范围整数 |
| `INT` / `INTEGER` | 4 字节 | -2,147,483,648～2,147,483,647 | 0～4,294,967,295 | 编号、数量 |
| `BIGINT` | 8 字节 | -2^63～2^63-1 | 0～2^64-1 | 大范围编号或计数 |
| `FLOAT` | 4 字节 | 近似值 | 近似值 | 对精度要求不高的小数 |
| `DOUBLE` | 8 字节 | 近似值 | 近似值 | 范围更大的近似小数 |
| `DECIMAL(M,D)` | 取决于精度 | 取决于 `M`、`D` | 可配合 `UNSIGNED` | 金额等精确小数 |

`M` 表示总位数，`D` 表示小数位数。例如，`DECIMAL(10, 2)` 最多保存 10 位数字，其中 2 位位于小数点后。

### 字符串类型

| 类型 | 特点 | 典型用途 |
| --- | --- | --- |
| `CHAR(n)` | 定长字符串，长度不足时会补齐 | 身份证号、固定编码 |
| `VARCHAR(n)` | 变长字符串，只保存实际内容 | 姓名、标题、地址 |
| `TINYTEXT` | 较短文本 | 简短说明 |
| `TEXT` | 最多约 64 KiB 的文本 | 正文、备注 |
| `MEDIUMTEXT` | 最多约 16 MiB 的文本 | 较长文章 |
| `LONGTEXT` | 最多约 4 GiB 的文本 | 超长文本内容 |
| `TINYBLOB` | 较短二进制数据 | 小型二进制内容 |
| `BLOB` | 最多约 64 KiB 的二进制数据 | 二进制内容 |
| `MEDIUMBLOB` | 最多约 16 MiB 的二进制数据 | 较大二进制内容 |
| `LONGBLOB` | 最多约 4 GiB 的二进制数据 | 超大二进制内容 |

`CHAR` 和 `VARCHAR` 的长度表示字符数；实际可存储内容还会受到字符集、行大小等因素影响。文本使用 `TEXT` 系列，原始二进制内容使用 `BLOB` 系列。

### 日期和时间类型

| 类型 | 存储空间 | 范围 | 格式 | 典型用途 |
| --- | ---: | --- | --- | --- |
| `DATE` | 3 字节 | 1000-01-01～9999-12-31 | `YYYY-MM-DD` | 生日、入职日期 |
| `TIME` | 3 字节 | -838:59:59～838:59:59 | `HH:MM:SS` | 时间或持续时长 |
| `YEAR` | 1 字节 | 1901～2155 | `YYYY` | 年份 |
| `DATETIME` | 8 字节 | 1000-01-01 00:00:00～9999-12-31 23:59:59 | `YYYY-MM-DD HH:MM:SS` | 与时区无关的日期时间 |
| `TIMESTAMP` | 4 字节 | 约 1970 年～2038 年 | `YYYY-MM-DD HH:MM:SS` | 创建时间、更新时间 |

`TIMESTAMP` 会受到会话时区转换的影响，而 `DATETIME` 按原值保存。选择类型时需要确认业务是否涉及跨时区处理。

## 修改表结构

修改已有表通常使用 `ALTER TABLE`。

### 添加字段

```sql
ALTER TABLE employee
ADD email VARCHAR(100) COMMENT '邮箱';
```

### 修改字段类型

`MODIFY` 只修改字段定义，不修改字段名：

```sql
ALTER TABLE employee
MODIFY name VARCHAR(50) COMMENT '姓名';
```

修改字段类型前，应确认已有数据都能转换为新类型，避免截断数据或执行失败。

### 修改字段名和类型

`CHANGE` 可以同时修改字段名和字段定义：

```sql
ALTER TABLE employee
CHANGE workno employee_no VARCHAR(20) COMMENT '员工编号';
```

### 删除字段

```sql
ALTER TABLE employee
DROP COLUMN email;
```

删除字段会同时删除该字段中的全部数据。

### 修改表名

```sql
ALTER TABLE employee
RENAME TO employee_info;
```

## 删除与清空表

删除整张表及其结构：

```sql
DROP TABLE IF EXISTS employee_info;
```

清空表中全部数据，但保留表结构：

```sql
TRUNCATE TABLE employee;
```

相关命令的区别如下：

| 命令 | 删除数据 | 删除表结构 | 是否可带 `WHERE` |
| --- | --- | --- | --- |
| `DELETE FROM 表名` | 是 | 否 | 是 |
| `TRUNCATE TABLE 表名` | 是，清空全部数据 | 否 | 否 |
| `DROP TABLE 表名` | 是 | 是 | 否 |

`TRUNCATE` 会清空数据并重置表的自增计数，但不会删除表定义。使用前仍需谨慎确认目标表。

## 容易混淆的点

- DDL 操作的是数据库对象的结构，DML 操作的是表中的数据。
- `DESC` 展示字段概要，`SHOW CREATE TABLE` 展示完整建表定义。
- `MODIFY` 修改字段定义；`CHANGE` 还可以修改字段名。
- `CHAR` 适合长度固定的数据，`VARCHAR` 适合长度可变的数据。
- `FLOAT` 和 `DOUBLE` 保存近似值；金额等要求精确计算的数据应优先使用 `DECIMAL`。
- `TRUNCATE` 保留表结构，`DROP TABLE` 连同表结构一起删除。

## 总结

DDL 用于管理数据库和表的结构。实际使用时，应掌握数据库的创建与选择、表结构的查看、字段数据类型的选择，以及通过 `ALTER TABLE` 修改表结构的方法。执行 `DROP`、`TRUNCATE` 或删除字段等操作前，需要特别确认影响范围，避免造成不可恢复的数据丢失。
