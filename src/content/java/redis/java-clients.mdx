# Redis Java 客户端、连接管理与序列化

Java 访问 Redis，需要明确三个问题：由哪个客户端建立连接，使用什么命令操作数据，以及 Java 对象如何转换成 Redis 能接收的字节。Jedis 用接近 Redis 命令的 API 展示这些过程；Spring Data Redis 则用模板统一数据访问与序列化。

理解主线是：**Java 类型决定代码如何使用数据，序列化决定数据如何编码，Redis 数据类型决定服务端允许执行哪些命令。** 三者相关，但不能互相替代。

## 一、客户端与模板分别负责什么

### 1. Jedis、Lettuce、Redisson 与 Spring Data Redis

| 名称 | 定位 | 本阶段需要掌握的内容 |
| --- | --- | --- |
| Jedis | Redis Java 客户端，方法名接近命令 | `set`、`get`、`hset`、`hgetAll`，以及连接池 |
| Lettuce | 基于 Netty 的 Redis Java 客户端，支持同步、异步和响应式 API | 本文 Boot 工程默认使用的底层客户端 |
| Redisson | 封装分布式锁、集合、信号量等能力的客户端 | 认识用途，具体功能另行学习 |
| Spring Data Redis | Spring 提供的数据访问抽象 | 连接工厂、RedisTemplate、StringRedisTemplate、序列化 |

Spring Data Redis 与 Jedis、Lettuce 不处于同一层。它可以通过不同的连接工厂使用底层客户端。本文的调用关系如下：

```text
业务代码 / JUnit 测试
    ↓
RedisTemplate / StringRedisTemplate
    ↓
RedisConnectionFactory
    ↓
Lettuce
    ↓ TCP 连接
Redis 服务端
```

Spring Boot 的 Redis Starter 默认引入 Lettuce。使用它时，不必再添加 Jedis，也不必手动创建 Lettuce 连接工厂；Boot 根据连接配置完成自动装配。参见 [Boot 3.0.2 Redis 自动配置说明](https://docs.spring.io/spring-boot/docs/3.0.2/reference/htmlsingle/#data.nosql.redis)。

### 2. 模板按 Redis 数据结构提供操作入口

| Java 调用 | 对应 Redis 结构 | 常用操作 |
| --- | --- | --- |
| `opsForValue()` | String | `set`、`get`、`increment` |
| `opsForHash()` | Hash | `put`、`get`、`entries` |
| `opsForList()` | List | 列表元素读写 |
| `opsForSet()` | Set | 无序集合操作 |
| `opsForZSet()` | Sorted Set | 带分数的有序集合操作 |
| 模板本身 | 键的通用操作 | `delete`、`expire`、`getExpire` |

`opsForValue()` 中的 Value 指 Redis String 的操作接口，不是所有数据结构的“值”。读取 Hash 必须使用 Hash 命令或 `opsForHash()`。

## 二、分清 Java 类型、序列化格式与 Redis 类型

### 1. Redis 不直接保存 Java 对象

Java 内存中的 `User` 不能原样跨网络发送给 Redis，需要先编码：

```text
Java User → JSON 文本 → UTF-8 字节 → Redis String
Redis String → UTF-8 字节解码 → JSON 文本 → Java User
```

序列化是把对象转换为可存储、可传输的表示；反序列化是按约定还原数据。JSON 是一种表示格式，并不是 Java 对象本身。

| 层次 | 例子 | 决定什么 |
| --- | --- | --- |
| Java 类型 | `String`、`User`、`Map<String, String>` | 编译器允许哪些调用、返回值如何使用 |
| 编码或序列化方式 | 字符串编码、JDK 序列化、JSON 序列化 | 最终写入哪些字节、读取时怎样解码 |
| Redis 数据类型 | String、Hash、List 等 | 可以执行 GET、HGET 或哪些其他命令 |

**`RedisTemplate<String, Object>` 的泛型不会自动把 key 变为可读字符串，也不会自动把 value 变为 JSON。** 泛型是 Java API 的类型声明；实际编码由序列化器决定。

### 2. “键用 String，值用 JSON”究竟是什么意思

在后文的自定义模板中：

- 顶层 key 使用字符串序列化，例如 `user:100`。
- 普通 value 使用 JSON 序列化，例如把整个 User 编码成 JSON。
- Hash 字段名使用字符串序列化，例如 `name`、`age`。
- Hash 字段值使用 JSON 序列化。

这描述的是**这个模板的编码约定**，并非所有 Redis 数据都必须采用 JSON。StringRedisTemplate 则把上述四处全部按字符串处理；字符串内容可以是普通文本，也可以是手动生成的 JSON。

```text
StringRedisTemplate 写入 "Jack"       → 普通文本 Jack
自动 JSON 模板写入 "Jack"             → JSON 字符串 "Jack"
StringRedisTemplate 写入 User 的 JSON → JSON 对象文本 {"name":"Jack","age":21}
```

前两种存储内容的字节不同。JSON 字符串的双引号是编码的一部分；CLI 为展示内容添加的外层引号、反斜杠又属于显示层，不能混为一谈。

### 3. JSON 字符串与 Redis Hash 是两种模型

同一份用户信息可以有两种存法：

```redis
SET user:200 '{"name":"Jack","age":21}'
HSET user:400 name Jack age 21
```

| 比较点 | 整个对象存 JSON | 对象字段拆成 Hash |
| --- | --- | --- |
| Redis 类型 | String | Hash |
| 读取整体 | `GET user:200` | `HGETALL user:400` |
| 读取姓名 | 取出 JSON，再解析 | `HGET user:400 name` |
| 修改年龄 | 普通 GET/SET 方案需要解析并重写整体 | `HSET user:400 age 22` |
| StringRedisTemplate 读回 | JSON 字符串 | 字段字符串或字符串 Map |
| 适用的简单场景 | 整体缓存、整体读取的对象 | 经常按字段读取或修改的记录 |

这里使用普通 Redis String 保存 JSON 文本，没有使用额外的 Redis JSON 文档功能。Redis 不会因为值长得像 JSON，就把它转换成 Hash。

`user:200` 中的冒号仅是键命名约定，便于客户端分组显示；它不表示数据库表、目录或数据类型。数据库编号也由连接选择，不由键名决定。

## 三、连接目标与 Redis 运行环境

### 1. Java 程序究竟连接哪里

连接目标由 **主机、端口、认证信息、数据库编号**共同确定。Java 与 RDM 要查看同一份数据，四项必须对应一致。

| Redis 运行位置 | Java 连接时使用的 host |
| --- | --- |
| Linux 虚拟机 | Windows 能访问的虚拟机 IP |
| Docker，端口发布到本机 | `127.0.0.1` |
| 远程服务器 | 对应服务器地址 |
| 与 Java 位于同一 Docker 网络的容器 | Compose 服务名，例如 `redis` |

`127.0.0.1` 指向当前程序所处的网络环境。Java 在 Windows 运行时它指本机；Java 在独立容器运行时它指该 Java 容器，不能直接照搬 Windows 的地址配置。

虚拟机中的 Redis 与 Docker 中的 Redis 是两个独立实例。切换连接后数据不会自动迁移；出现“原来的数据不见了”时，应先核对目标实例。

### 2. 虚拟机已开机，为什么仍可能连不上

启动虚拟机只说明 Linux 系统已启动，不保证 Redis 进程正在运行。如果已配置 systemd 服务，可以在虚拟机中执行：

```bash
sudo systemctl start redis
sudo systemctl status redis
```

服务名以安装时创建的 unit 为准。若没有注册服务，可使用实际的配置文件路径启动：

```bash
redis-server /实际路径/redis.conf
```

是否后台运行取决于配置；完整安装与服务管理参见 [Redis 基础与环境搭建](/docs/java/redis/)。之后仍要验证监听端口、认证与 PING，而不是只检查虚拟机状态。

### 3. Docker 启动 Redis 的可复用配置

Docker 是运行 Redis 的另一种方式，不要求维护一台专门安装 Redis 的课程虚拟机。在 Windows 上使用 Docker Desktop 的 Linux 容器引擎；底层仍可能依赖 WSL2 等虚拟化能力。

以下为独立的本机练习配置。密码 `redis-demo-password` 是示例值，已有实例应沿用其实际密码，不要为了匹配文档直接改动服务端。

目录结构：

```text
redis-docker/
├─ compose.yaml
└─ redis.conf
```

**`compose.yaml`：**

```yaml
services:
  redis:
    image: redis:7.4
    container_name: redis-learn
    restart: unless-stopped
    ports:
      - "127.0.0.1:6379:6379"
    volumes:
      - redis-data:/data
      - ./redis.conf:/usr/local/etc/redis/redis.conf:ro
    command: ["redis-server", "/usr/local/etc/redis/redis.conf"]

volumes:
  redis-data:
```

**`redis.conf`：**

```conf
bind 0.0.0.0
port 6379
protected-mode yes
requirepass redis-demo-password
dir /data
appendonly yes
```

配置文件必须先创建为文件，再启动容器。已有名为 `redis-learn` 的容器时，应先确认是否就是现有练习环境，不重复创建同名容器。

| 配置 | 含义 |
| --- | --- |
| `127.0.0.1:6379:6379` | 宿主机本地地址与端口映射到容器的 6379 端口 |
| `bind 0.0.0.0` | Redis 在容器内部监听网络接口；宿主机发布范围仍由 ports 决定 |
| `redis-data:/data` | 使用命名卷保存数据文件 |
| `:ro` | 配置文件在容器内只读 |
| `appendonly yes` | 启用 AOF 持久化；具体落盘保证仍取决于同步策略 |
| `restart: unless-stopped` | Docker 引擎可用时按该策略重启；不等于系统无需启动 Docker |

端口发布的语法参见 [Docker Compose ports 配置](https://docs.docker.com/reference/compose-file/services/#ports)。

在上述目录打开 PowerShell：

```powershell
docker compose up -d
docker compose ps
docker exec -it redis-learn redis-cli
```

进入 Redis CLI 后：

```redis
AUTH redis-demo-password
SELECT 0
PING
```

预期返回 `OK`、`OK`、`PONG`。`docker compose up -d` 创建并在后台启动服务，参见 [Compose up 文档](https://docs.docker.com/reference/cli/docker/compose/up/)。

日常管理：

```powershell
docker compose stop
docker compose start
docker compose logs --tail 50 redis
```

`stop` 停止容器，`start` 启动已有容器；修改 Compose 配置后使用 `up -d` 应用变更。修改挂载的 Redis 配置后，需要让 Redis 重启读取配置。命名卷用于保留数据，`down -v` 会删除关联命名卷，不用于普通停机。

### 4. 分层验证连接

Windows 先检查端口：

```powershell
Test-NetConnection 127.0.0.1 -Port 6379
```

再从 RDM 连接 `127.0.0.1:6379`，使用实际密码并选择 DB0。

- 端口测试成功：TCP 连接能够建立。
- `PING` 返回 `PONG`：Redis 已响应命令；启用认证时还需先完成认证。
- Java 测试成功且 RDM 能看到同一键：连接目标、认证和读写链路基本一致。

容器内部 PING 成功仅验证容器内部服务；Windows Java 的连接仍需要通过发布端口验证。

### 2. 直连、认证、读写与关闭

**`src/test/java/com/itfuck/JedisTest.java`：**

```java
package com.itfuck;

import org.junit.jupiter.api.AfterEach;
import org.junit.jupiter.api.BeforeEach;
import org.junit.jupiter.api.Test;
import redis.clients.jedis.Jedis;

import java.util.Map;

import static org.junit.jupiter.api.Assertions.assertEquals;

class JedisTest {
    private Jedis jedis;

    @BeforeEach
    void setUp() {
        String host = System.getenv().getOrDefault("REDIS_HOST", "127.0.0.1");
        String password = System.getenv().getOrDefault(
                "REDIS_PASSWORD", "redis-demo-password");
        jedis = new Jedis(host, 6379, 2000);
        jedis.auth(password);
        jedis.select(0);
    }

    @Test
    void testConnection() {
        assertEquals("PONG", jedis.ping());
    }

    @Test
    void testString() {
        assertEquals("OK", jedis.set("name", "Jack"));
        assertEquals("Jack", jedis.get("name"));
    }

    @Test
    void testHash() {
        jedis.hset("user:1", "name", "Jack");
        jedis.hset("user:1", "age", "21");
        Map<String, String> user = jedis.hgetAll("user:1");
        assertEquals("Jack", user.get("name"));
        assertEquals("21", user.get("age"));
    }

    @AfterEach
    void tearDown() {
        if (jedis != null) {
            jedis.close();
        }
    }
}
```

流程是 **建立连接 → 认证 → 选择数据库 → 执行命令 → 释放资源**。示例使用环境变量覆盖连接目标；在 IDEA 运行时，需要在对应 Run Configuration 配置环境变量。

| Java 方法 | Redis 命令 | 返回值的含义 |
| --- | --- | --- |
| `ping()` | PING | 正常返回 `PONG` |
| `set(key, value)` | SET | 成功返回 `OK` |
| `get(key)` | GET | 字符串，不存在时为 `null` |
| `hset(key, field, value)` | HSET | 本示例重载返回新增字段数量 |
| `hgetAll(key)` | HGETALL | 字段与值组成的 Map |

例如：

```java
jedis.hset("user:1", "age", "22");
```

如果 `age` 已存在，就将它的值覆盖为 `22`，`name` 不变；如果字段不存在则新增。已有字段被覆盖时，HSET 的新增字段计数为 `0`，不代表更新失败。`"22"` 是 Java 字符串，Redis Hash 字段值仍按字符串字节存储。参见 [HSET 命令说明](https://redis.io/docs/latest/commands/hset/)。

## 五、连接池：复用连接与管理生命周期

### 1. 为什么引入连接池

反复建立和销毁 TCP 连接有额外开销；把同一个 Jedis 实例交给多个线程并发操作，又可能造成连接使用冲突。连接池保存可复用连接，每次使用借出一个资源，用完归还。

```text
应用共享一个 JedisPool
    ├─ 请求 A：借连接 → 操作 → 归还
    ├─ 请求 B：借连接 → 操作 → 归还
    └─ 请求 C：无可用连接时等待，或等待超时
```

池可以共享，借出的 Jedis 不应被多个线程随意共用。连接池复用的是连接，线程池管理的是执行任务的线程，两者职责不同。

### 2. Jedis 连接工厂

**`src/main/java/com/itfuck/util/JedisConnectionFactory.java`：**

```java
package com.itfuck.util;

import redis.clients.jedis.Jedis;
import redis.clients.jedis.JedisPool;
import redis.clients.jedis.JedisPoolConfig;

public final class JedisConnectionFactory {
    private static final JedisPool POOL;

    static {
        JedisPoolConfig config = new JedisPoolConfig();
        config.setMaxTotal(8);
        config.setMaxIdle(8);
        config.setMinIdle(0);
        config.setMaxWaitMillis(1000);

        String host = System.getenv().getOrDefault("REDIS_HOST", "127.0.0.1");
        String password = System.getenv().getOrDefault(
                "REDIS_PASSWORD", "redis-demo-password");
        POOL = new JedisPool(config, host, 6379, 2000, password);
    }

    private JedisConnectionFactory() {
    }

    public static Jedis getJedis() {
        return POOL.getResource();
    }

    public static void shutdown() {
        POOL.close();
    }
}
```

| 参数 | 示例 | 含义 |
| --- | --- | --- |
| `maxTotal` | 8 | 最大连接总数，包括已借出与空闲连接 |
| `maxIdle` | 8 | 最多保留多少空闲连接，不是启动时立即创建的数量 |
| `minIdle` | 0 | 最小空闲目标，实际维护还受检测与回收配置影响 |
| `maxWaitMillis` | 1000 | 池耗尽后，借资源最多等待多久 |
| 构造器 `timeout` | 2000 | 该 Jedis 重载的连接与读写超时设置，与借池等待不同 |

把 `JedisTest` 的 `setUp()` 替换为：

```java
@BeforeEach
void setUp() {
    jedis = JedisConnectionFactory.getJedis();
    jedis.select(0);
}
```

同时增加 `import com.itfuck.util.JedisConnectionFactory;`。池已经负责认证，不需要每次再写 `auth`；保留原来的测试方法和 `tearDown()`。

### 3. 为什么连接池中的连接也必须 close

| 资源来源 | `close()` 的作用 |
| --- | --- |
| `new Jedis(...)` | 关闭普通连接 |
| `JedisPool.getResource()` | 正常资源归还池中；损坏连接由池处理 |
| `JedisPool` 本身 | 关闭整个池，供应用结束时统一调用 |

普通业务代码优先利用 `try-with-resources` 保证异常时也能释放：

```java
try (Jedis jedis = JedisConnectionFactory.getJedis()) {
    String name = jedis.get("name");
    System.out.println(name);
}
```

这里退出代码块时归还当前连接，不是关闭整个池。`shutdown()` 应在整个示例应用结束时调用，不在每个测试或每个请求后调用，否则后续借用会失败。

### 4. Lettuce 的池化不能照搬 Jedis 理解

Jedis 的典型使用方式是每次借独立连接。Spring 的 LettuceConnectionFactory 默认可以让普通非阻塞、非事务操作共享线程安全的底层原生连接；阻塞、事务等连接使用方式不同。

因此，加入 Commons Pool 和配置池大小，不表示每一次普通 `GET` 都会从池中借一个独立 TCP 连接。是否共享原生连接与具体操作类型同样影响连接使用。模板由 Spring 管理，普通模板调用后无需手动 `close()`。参见 [Spring Data Redis 的连接说明](https://docs.spring.io/spring-data/redis/docs/3.0.1/reference/html/#redis:connectors:lettuce)。

## 六、Spring Boot 工程与版本配置

### 1. 固定版本，避免混用配置

本文使用 Java 17、Spring Boot 3.0.2、Jedis 3.7.0，以及 Docker 中的 Redis 7.4。这里固定版本用于复现实验，不代表新项目的版本选型建议。

| 对比项 | 旧课程环境 | 本文实操环境 |
| --- | --- | --- |
| Java | 8 | 17 |
| Spring Boot | 2.5.7 | 3.0.2 |

## 七、默认 JDK 序列化与四个序列化位置

### 1. 为什么 Java 成功，CLI 却查不到 name

未自定义的普通 RedisTemplate 默认采用 JDK 序列化。Java 字符串 `name` 经它编码后，字节不同于字符串编码的 `name`。

```text
CLI / Jedis 的字符串键： UTF-8("name")
默认模板的键：          JDK 对象序列化("name")
```

因此两个客户端可能都认为操作了 `name`，实际访问的却是不同的 Redis 键。默认模板写入后，Java 能按同一规则读回；CLI 执行 `GET name` 仍读取普通字符串键。RDM 可能把另一个键显示为带二进制转义前缀的内容。

排查顺序是：先确认同一实例与 DB，再比较序列化方式。不能仅凭 Java 测试通过，就认定其他客户端也能按相同文本键访问。

默认 JDK 序列化还要求被序列化的对象满足相应条件，例如普通 POJO 使用它时通常需要实现 Serializable。后文的 JSON User 示例不依赖 Java 的 Serializable 接口。

### 2. 四个序列化器分别控制哪里

| 设置 | 负责的数据 | 字符串键 + JSON 值方案 | StringRedisTemplate |
| --- | --- | --- | --- |
| `keySerializer` | 顶层 key，如 `user:100` | String | String |
| `valueSerializer` | 普通 value，如 User | JSON | String |
| `hashKeySerializer` | Hash 字段名，如 `age` | String | String |
| `hashValueSerializer` | Hash 字段值，如 `21` | JSON | String |

顶层 key 与 Hash 内部 field 是两个层次，设置 keySerializer 不会顺带设置 hashKeySerializer。默认模板与字符串模板的差异可参见 [Spring Data Redis 序列化说明](https://docs.spring.io/spring-data/redis/docs/3.0.1/reference/html/#redis:serializer)。

**修改序列化器不会迁移旧数据。** 原有二进制键仍可能存在；同一个文本键下的旧值也不会自动重编码。练习不同方案时使用不同键，避免把格式冲突误认为连接异常。

## 八、自动 JSON 序列化：RedisTemplate

### 1. 注册自定义模板

**`src/main/java/com/itfuck/redisdemo2/config/RedisConfig.java`：**

```java
package com.itfuck.redisdemo2.config;

import org.springframework.context.annotation.Bean;
import org.springframework.context.annotation.Configuration;
import org.springframework.data.redis.connection.RedisConnectionFactory;
import org.springframework.data.redis.core.RedisTemplate;
import org.springframework.data.redis.serializer.GenericJackson2JsonRedisSerializer;
import org.springframework.data.redis.serializer.RedisSerializer;

@Configuration
public class RedisConfig {
    @Bean
    public RedisTemplate<String, Object> redisTemplate(
            RedisConnectionFactory connectionFactory) {
        RedisTemplate<String, Object> template = new RedisTemplate<>();
        template.setConnectionFactory(connectionFactory);

        GenericJackson2JsonRedisSerializer jsonSerializer =
                new GenericJackson2JsonRedisSerializer();
        template.setKeySerializer(RedisSerializer.string());
        template.setHashKeySerializer(RedisSerializer.string());
        template.setValueSerializer(jsonSerializer);
        template.setHashValueSerializer(jsonSerializer);
        return template;
    }
}
```

连接工厂由 Boot 提供，模板只负责绑定工厂和设置序列化规则。`@Configuration` 声明配置类，`@Bean` 把返回对象交给 Spring 管理；方法名 `redisTemplate` 对应这里的自定义模板 Bean。

### 2. 用户对象

**`src/main/java/com/itfuck/redisdemo2/pojo/User.java`：**

```java
package com.itfuck.redisdemo2.pojo;

import lombok.AllArgsConstructor;
import lombok.Data;
import lombok.NoArgsConstructor;

@Data
@NoArgsConstructor
@AllArgsConstructor
public class User {
    private String name;
    private Integer age;
```

`@Data` 生成 getter、setter、toString、equals/hashCode 等；无参构造和 setter 让本例可按默认 Bean 方式还原；全参构造便于创建测试对象。无参构造是此示例的还原方式，不代表 Jackson 只能通过无参构造创建对象。

### 3. 对象往返与类型信息

**`src/test/java/com/itfuck/redisdemo2/RedisDemo2ApplicationTests.java`：**

```java
package com.itfuck.redisdemo2;

import com.itfuck.redisdemo2.pojo.User;
import org.junit.jupiter.api.Test;
import org.springframework.beans.factory.annotation.Autowired;
import org.springframework.boot.test.context.SpringBootTest;
import org.springframework.data.redis.core.RedisTemplate;

import static org.junit.jupiter.api.Assertions.assertEquals;
import static org.junit.jupiter.api.Assertions.assertInstanceOf;

@SpringBootTest
class RedisDemo2ApplicationTests {
    @Autowired
    private RedisTemplate<String, Object> redisTemplate;

    @Test
    void testString() {
        redisTemplate.opsForValue().set("json:name", "Jack");
        assertEquals("Jack", redisTemplate.opsForValue().get("json:name"));
    }

    @Test
    void testSaveUser() {
        User original = new User("Jack", 21);
        redisTemplate.opsForValue().set("user:100", original);
        Object value = redisTemplate.opsForValue().get("user:100");
        User restored = assertInstanceOf(User.class, value);
        assertEquals(original, restored);
    }

```

在此版本的无参 GenericJackson2JsonRedisSerializer 下，User 的存储内容类似：

```json
{
  "@class": "com.itfuck.redisdemo2.pojo.User",
  "name": "Jack",
  "age": 21
}
```

`@class` 保存完整 Java 类名，用于告诉反序列化器要还原成哪种对象；它不是 `.class` 文件、字节码或对象内存地址。不同序列化配置的类型元数据格式可能不同，不能把这个示例推广成“所有 JSON 都有 @class”。

自动方案读取后之所以能得到 User，是反序列化器已经创建了 User。**强制类型转换只检查或声明已有对象的类型，不负责解析 JSON，也不会把 String 或 Map 变成 User。**

类名增加了数据体积，也使缓存内容与 Java 包名存在耦合。重命名类或调整包结构时，要考虑现有缓存的兼容与失效。

## 九、ObjectMapper 与手动 JSON 转换

### 1. ObjectMapper 是什么

ObjectMapper 是 Jackson 提供的 JSON 数据绑定工具，负责 Java 数据与 JSON 之间的转换，不负责连接 Redis。

| 工具 | 职责 |
| --- | --- |
| ObjectMapper | 对象转 JSON、JSON 转指定 Java 类型 |
| StringRedisTemplate | 把字符串写入 Redis、从 Redis 读出字符串 |
| Redis | 按数据结构保存与操作数据 |

```java
ObjectMapper mapper = new ObjectMapper();
String json = mapper.writeValueAsString(new User("Jack", 21));
User user = mapper.readValue(json, User.class);
```

`writeValueAsString` 返回 Java String，内容为 `{"name":"Jack","age":21}`；`readValue` 根据 User.class 与 JSON 字段创建并填充 User。

不能用 `toString()` 代替 JSON 序列化。Lombok 的输出如 `User(name=Jack, age=21)` 是调试文本，不是合法的 JSON 对象。

### 2. 为什么手动 JSON 通常不需要 @class

读取时已明确传入 `User.class`，JSON 无需再保存完整类名。JSON 文本包含业务字段，程序通过目标类型补足还原信息。

```text
User
  → writeValueAsString
JSON 字符串
  → StringRedisTemplate.set
Redis String
  → StringRedisTemplate.get
JSON 字符串
  → readValue(json, User.class)
User
```

`StringRedisTemplate` 不会自动调用 ObjectMapper。直接把 User 传给它的 set 方法，会因为参数应为 String 而编译失败。

### 3. ObjectMapper 的创建与复用

本例使用 `private static final ObjectMapper MAPPER = new ObjectMapper();`，避免每次转换都重新创建。

Jackson 2 的 ObjectMapper 在首次读写前完成配置、之后不再修改配置时，可以复用并供多线程调用。复杂工程可统一提供 Mapper Bean，集中配置日期、命名规则或模块；示例中的普通字符串与整数不需要额外模块。参见 [Jackson 2.14 ObjectMapper 说明](https://github.com/FasterXML/jackson-databind/blob/2.14/src/main/java/com/fasterxml/jackson/databind/ObjectMapper.java)。

Boot 可以在满足条件时自动配置 ObjectMapper，不能单凭“没有 Web Starter”就断定一定没有该 Bean。手动创建的 Mapper 也不会自动继承容器中另一个 Mapper 的配置，两者需要区分。

### 4. 完整的字符串、对象与 Hash 测试

**`src/test/java/com/itfuck/redisdemo2/RedisStringTest.java`：**

```java
package com.itfuck.redisdemo2;

import com.fasterxml.jackson.core.JsonProcessingException;
import com.fasterxml.jackson.databind.ObjectMapper;
import com.itfuck.redisdemo2.pojo.User;
import org.junit.jupiter.api.Test;
import org.springframework.beans.factory.annotation.Autowired;
import org.springframework.boot.test.context.SpringBootTest;
import org.springframework.data.redis.core.HashOperations;
import org.springframework.data.redis.core.StringRedisTemplate;

import java.util.Map;

import static org.junit.jupiter.api.Assertions.assertEquals;
import static org.junit.jupiter.api.Assertions.assertNotNull;

@SpringBootTest
class RedisStringTest {
    @Autowired
    private StringRedisTemplate stringRedisTemplate;

    private static final ObjectMapper MAPPER = new ObjectMapper();

    @Test
    void testString() {
        stringRedisTemplate.opsForValue().set("name", "Jack");
        assertEquals("Jack", stringRedisTemplate.opsForValue().get("name"));
    }

    @Test
    void testSaveUser() throws JsonProcessingException {
        User original = new User("Jack", 21);
        String json = MAPPER.writeValueAsString(original);
        stringRedisTemplate.opsForValue().set("user:200", json);

        String stored = stringRedisTemplate.opsForValue().get("user:200");
        assertNotNull(stored);
        User restored = MAPPER.readValue(stored, User.class);
        assertEquals(original, restored);
    }

    @Test
    void testHash() {
        HashOperations<String, String, String> hash =
                stringRedisTemplate.opsForHash();
        hash.put("user:400", "name", "Jack");
        hash.put("user:400", "age", "21");

        String name = hash.get("user:400", "name");
        Map<String, String> user = hash.entries("user:400");
        assertEquals("Jack", name);
        assertEquals("21", user.get("age"));
    }

    @Test
    void testUpdateUser() {
        HashOperations<String, String, String> hash =
                stringRedisTemplate.opsForHash();
        hash.put("user:500", "name", "Alice");
        hash.put("user:500", "age", "20");
        hash.put("user:500", "age", "21");

        Map<String, String> user = hash.entries("user:500");
        assertEquals("Alice", user.get("name"));
        assertEquals("21", user.get("age"));
    }
}
```

两个模板可以共存：对象模板注入 RedisTemplate，字符串模板注入 StringRedisTemplate。自定义 RedisConfig 只配置它创建的模板，不会自动把字符串模板也改成 JSON 序列化。

`get` 在键不存在时可能返回 null，因此先判断再解析。测试使用断言明确数据必须存在；业务代码则应按“缓存未命中”或“数据不存在”的语义处理。

`JsonProcessingException` 表示 JSON 转换可能失败。测试方法可以声明 throws，业务层需要结合错误处理策略决定如何处理，不能通过强制转换绕过解析。

### 5. 自动 JSON 与手动 JSON 如何选择

| 比较项 | 自定义 RedisTemplate 自动 JSON | StringRedisTemplate + ObjectMapper |
| --- | --- | --- |
| 写入参数 | User 对象 | JSON 字符串 |
| 谁转换格式 | 模板配置的 JSON 序列化器 | 业务代码调用 Mapper |
| 读取返回 | 本例按类型元数据还原为 User | 先返回 String，再指定目标类型解析 |
| 本例内容 | 业务字段与完整类名 | 业务字段 |
| 维护约定 | 序列化配置与类型元数据 | JSON 字段与目标类型 |

手动 JSON 使存储格式和目标类型更明确，也便于其他语言读取。自动方案减少显式转换代码。选择取决于数据协议和项目约定，不等于所有对象都必须手动转换。

同一个键应保持稳定的编码约定。不要把已生成的 JSON 字符串再交给自动 JSON 模板当对象写入，否则可能得到带转义的“JSON 字符串”，而不是原来的 JSON 对象文本。

## 十、Hash 泛型与字段更新

### 1. 三个泛型分别表示什么

```java
HashOperations<String, String, String> hash =
        stringRedisTemplate.opsForHash();
//             K       HK      HV
//             顶层键   字段名   字段值
```

对于 `hash.put("user:400", "age", "21")`：

| 参数 | 内容 | 所属层次 |
| --- | --- | --- |
| K | `user:400` | Redis 顶层 key |
| HK | `age` | Hash 内部 field |
| HV | `21` | 字段对应的 value |

本例使用字符串序列化，所以三个泛型都声明为 String。Java 泛型表达代码中的类型预期，不能代替序列化配置。

### 2. Object 无法转换成 String 的原因

下面的声明把字段值返回类型定义成了 Object：

```java
HashOperations<String, Object, Object> hash =
        stringRedisTemplate.opsForHash();
Object name = hash.get("user:400", "name");
```

此时直接写 `String name = hash.get(...)`，编译器会提示 `java.lang.Object 无法转换为 java.lang.String`。即使 Redis 中确实存的是字符串，编译器仍按声明的类型检查代码。

对于当前全部使用字符串的场景，应统一声明：

```java
HashOperations<String, String, String> hash =
        stringRedisTemplate.opsForHash();
String name = hash.get("user:400", "name");
Map<String, String> user = hash.entries("user:400");
```

不需要为解决这个问题修改 Redis 数据，更不需要重装 Redis。强转虽然可能通过编译，但会保留类型假设和运行时风险；明确正确泛型更合适。

### 3. Hash 常用操作

| API | 对应含义 | 返回值 |
| --- | --- | --- |
| `put(key, field, value)` | HSET，一个字段新增或覆盖 | void |
| `putAll(key, map)` | 多个字段写入 | void |
| `get(key, field)` | HGET | 字段值或 null |
| `entries(key)` | HGETALL | 字段与值的 Map |
| `keys(key)` | HKEYS | 该 Hash 的字段名集合 |
| `values(key)` | HVALS | 该 Hash 的字段值列表 |
| `delete(key, fields...)` | HDEL | 删除字段的数量 |

`hash.keys("user:400")` 返回 name、age 等字段名，不是整个数据库的顶层键。`stringRedisTemplate.delete("user:400")` 才是删除整个 Redis 键。

同一字段再次 put 会覆盖旧值，其他字段不变；`testUpdateUser` 最终保留 Alice，并把年龄改成字符串 `21`。Map 的遍历顺序不保证，应按键断言结果。

### 4. 年龄为什么写成字符串

StringRedisTemplate 使用字符串序列化，Hash 字段值传入 `"21"`。需要 Java 整数时再显式转换：

```java
String ageText = hash.get("user:400", "age");
if (ageText != null) {
    int age = Integer.parseInt(ageText);
}
```

Redis Hash 字段值并不自带 Java Integer 类型。JSON 中的 `"age":21` 则是 JSON 数字，Mapper 可根据 User.age 的 Integer 类型还原。

对于数字字段，Redis 也提供 HINCRBY，Spring 对应 `hash.increment("user:400", "age", 1L)`。它在服务端完成单次原子增量；字段内容必须能按相应数值规则解析，不能把任意文本直接递增。

## 十一、运行、核对与独立复现

### 1. 用测试作为入口

在各自项目根目录运行：

```powershell
# jedis-demo
mvn test

# redis-demo-2
mvn '-Dtest=RedisDemo2ApplicationTests' test
mvn '-Dtest=RedisStringTest' test
```

只运行一个方法时：

```powershell
mvn '-Dtest=RedisStringTest#testSaveUser' test
```

PowerShell 中给完整的 `-Dtest=...` 参数加引号。IDEA 也可以点击测试方法旁的运行按钮；两种方式应使用一致的 JDK、环境变量与依赖。

`@BeforeEach` 在每个测试前执行，`@AfterEach` 在每个测试后执行，`@Test` 声明测试方法，`@SpringBootTest` 加载 Boot 测试上下文。`assertEquals` 不只是打印结果，而是结果不符时让测试失败。

本文的自动 JSON 字符串示例使用 `json:name`，普通字符串示例使用 `name`，减少测试之间的格式覆盖。不要依赖 JUnit 默认的测试方法执行顺序。

这些工程没有 Web Starter、Controller 或页面，直接运行启动类后没有网页属于正常现象。本阶段从 JUnit 测试验证 Redis 调用。

### 2. 在 Redis 端核对

示例会写入以下练习键。使用独立练习实例；已有同名业务键时，应先更换示例键名。

```redis
SELECT 0
GET name
GET json:name
TYPE user:1
HGETALL user:1
TYPE user:100
GET user:100
TYPE user:200
GET user:200
TYPE user:400
HGETALL user:400
HGETALL user:500
```

| 键 | Redis 类型 | 预期内容 |
| --- | --- | --- |
| `name` | String | 普通文本 Jack |
| `json:name` | String | JSON 字符串形式的 Jack，包含 JSON 引号 |
| `user:1` | Hash | Jedis 测试写入 name=Jack、age=21 |
| `user:100` | String | 带 @class 的 User JSON |
| `user:200` | String | 不带 @class 的 User JSON |
| `user:400` | Hash | name=Jack、age=21 |
| `user:500` | Hash | name=Alice、age=21 |

若在测试之外执行过 `hset("user:1", "age", "22")`，年龄应按最后一次实际写入核对；重跑 testHash 会再次写为 21。

RDM 是另一个 Redis 客户端，不是 Java 工程的数据副本。Java 写入成功后，在 RDM 选择同一实例、同一 DB 并刷新，即可查看相同数据。必要时用 `TYPE key` 确认类型；对 Hash 执行 GET 会产生 WRONGTYPE。

### 3. 独立复现所需的能力

- 配置并验证一个 Redis 实例，区分端口可达、认证成功与读写成功。
- 创建 Maven 工程，理解依赖、测试插件和 Java 版本的作用。
- 使用 Jedis 操作 String 与 Hash，并正确归还连接。
- 创建 Boot 工程，使用与版本一致的 Redis 配置前缀。
- 说明模板泛型与四个序列化器的区别。
- 完成 User 的自动 JSON 往返与手动 JSON 往返。
- 根据访问方式选择 JSON String 或 Hash，并独立完成字段更新。

## 十二、常见异常与定位方法

### 1. 先读异常链中的具体原因

```text
Could not get a resource from the pool
    ↓ Caused by
WRONGPASS invalid username-password pair or user is disabled
```

上层表示“未能取得可用连接”，下层说明这次失败发生在认证。**不能看到 pool 就认定连接池太小。** 认证失败会使借连接失败，网络超时也可能包装成相同的上层异常。

```text
Failed to create socket
    ↓ Caused by
SocketTimeoutException: Connect timed out
```

这表示连接建立阶段超时，应先检查 Redis 是否启动、目标地址、端口、网络和监听配置。仅凭这条异常不能断定密码错误，也不能断定只有一种网络原因。

### 2. 按现象定位

| 现象 | 含义或优先检查项 | 处理方向 |
| --- | --- | --- |
| Connect timed out | TCP 连接在规定时间内未建立 | 检查虚拟机或 Docker、IP、端口、网络与监听 |
| Connection refused | 目标拒绝建立连接 | 检查服务是否监听，以及端口映射 |
| NOAUTH | 尚未认证 | 补充实际实例的认证配置 |
| WRONGPASS | 密码、ACL 用户名或用户状态不匹配 | 对照 RDM 的实际目标与认证；必要时检查 username |
| Could not get a resource from the pool | 表层借连接失败 | 继续读 Caused by，区分网络、认证与资源耗尽 |
| 借池等待超时 | 可能未归还或连接被长期占用 | 核对 close、并发与耗时，再考虑池容量 |
| Object 无法转换成 String | Java 泛型返回类型不匹配 | 使用正确的 HashOperations 泛型 |
| WRONGTYPE | 命令与 Redis 实际类型不一致 | TYPE 后选择 GET 或 HGET 等正确命令 |
| User 强转失败 | 实际返回的是 String、Map 或其他类型 | 核对序列化方案；JSON 文本用 readValue |
| JSON 解析失败 | 内容格式、目标类型或旧数据约定不一致 | 查看原始内容，避免不同模板交叉写同一键 |
| 找不到 ObjectMapper 等类 | Jackson 依赖缺失或未加载 | 检查 jackson-databind 和 Maven 导入 |
| 找不到 Boot 启动配置 | 主类与测试的包层级不匹配 | 对照目录结构和启动类注解 |
| Lombok 构造方法不存在 | 依赖、注解处理或 IDE 支持问题 | 刷新 Maven，检查注解处理，或手写等价方法 |
| Maven 没发现 JUnit 5 测试 | 测试目录、命名、JUnit 导入或 Surefire 配置 | 使用 Jupiter 注解，检查测试插件 |
| Java 成功，RDM 看不到 | 目标实例、DB、刷新或键编码不同 | 对齐连接后再核对序列化 |

### 3. SLF4J 警告与 Redis 异常要区分

```text
SLF4J: Failed to load class "org.slf4j.impl.StaticLoggerBinder".
SLF4J: Defaulting to no-operation (NOP) logger implementation
```

在使用旧版 SLF4J API 的 Jedis 示例中，这表示没有匹配的日志实现，日志调用退化为空操作。它会影响日志输出，但不是后续 Connect timed out 或 WRONGPASS 的直接原因。

若需要补日志实现，应与当前 SLF4J API 版本匹配；不要把 Boot 已管理的日志依赖任意替换成另一套版本。排查连接失败时，优先处理异常链中实际的网络或认证原因。

### 4. 调整配置与处理旧数据

- 切换 VM 与 Docker：同时修改 Java 和 RDM 的目标地址，数据迁移需要另行处理。
- 改直连为连接池：核对工厂中的密码，不能只修改已经不再使用的旧 setUp。
- 改 Boot 版本：核对配置前缀，避免 YAML 看似正确但没有绑定到预期属性。
- 改序列化方案：使用新的练习键或明确重写指定数据，不期待旧键自动迁移。
- 需要删除错误练习数据时：先确认实例、DB 与键名，只处理明确的练习键，无需清空整个数据库。

## 十三、与业务缓存学习的衔接

客户端、连接池和序列化解决“怎样访问 Redis”；业务缓存还要解决“何时读写 Redis、未命中怎么办、数据库修改后如何失效”。后续可进入 [Redis 业务缓存](/docs/java/redis/shop-cache/)，学习查询回填、缓存更新、穿透、雪崩与击穿。

Redis 保存验证码和登录状态是另一类应用。为优先学习缓存，可以暂缓登录模块；若使用黑马点评代码，仍需要先完成项目导入和数据库等环境准备，不能把项目准备一并省略。
