## 五、Java 后端应补到什么程度

### 1. Java 语言与工程约定

围绕当前已有代码确认以下能力：

- 对象、引用、接口、继承、访问修饰符。
- 常用 List/Map/Set、泛型、Lambda、方法引用。
- 异常传播、try/finally、资源与线程中断的基本处理。
- Maven 依赖、scope、main/test 目录、配置和测试运行。
- Spring Bean、注入、Controller/Service/Mapper、请求参数与对象转换。
- 会跟踪“输入从哪里来、对象由谁创建、数据库何时被调用、错误如何返回”。

有缺口就局部补，不因为已有学习笔记认定全部掌握，也不因一次目录错误重置为零基础。

### 2. 数据库与缓存

- 自己画表并解释关系、约束、分页与查询条件。
- 事务边界、常见并发问题、原子条件更新。
- 能用 EXPLAIN 检查实际查询，结合 WHERE/ORDER BY 选择必要索引。
- 缓存读写、空值、TTL、更新失效、穿透/击穿/雪崩。
- 能解释“单库事务不自动保证 MySQL 与 Redis 原子提交”。
- Redis 锁补到所有权、原子校验释放、租期边界和成熟客户端基本用法；不把原计划 P60 当作完整安全锁学习的终点，也不扩大为整套集群运维和锁源码课程。新增回看范围在实际带学时核对。

### 3. 并发与中间件

- 理解共享数据、原子性与基本可见性问题。
- 会使用并解释线程池的队列、任务提交、异常、关闭及容量选择。
- ThreadLocal 的请求上下文与 remove，理解异步任务的上下文边界。
- 按需要学习 CompletableFuture、CountDownLatch。
- MQ 先选一种，能处理重复消息、失败重试与基本幂等；Kafka/RocketMQ 等不并行开多条完整课程。
- AQS、锁升级、Redis 底层源码等列为后续可选，当前不作求职前的统一门槛。

黑马点评用于完成缓存和并发训练。随后固定以天机学堂为实做主线：课程复现、自己运行验收，再完成一条独立的前后端业务扩展。前端沿用熟悉的框架，不另开一套基础课程。

公司 IoT 采用源码带读：业务场景 → 请求与对象 → Controller/用例 → 端口与远程调用 → 仓储/SQL → 响应和异常。每周两次约1小时，包含在总学习预算内；其余时间优先主项目。只选2–3条代表链路，不通读四个服务全部代码。讲解验收为能定位关键类、画调用链、解释校验和失败路径、推演需求改动范围。未运行行为明确记为静态推断。

阅读和复现不能直接记为过去在职承担过后端生产职责，不编造流量指标、上线事故或个人贡献。已有九年前端项目经历可以作为真实履历主体，后续学习成果用于证明新增后端能力。

主作品至少要有一条由自己独立完成的功能：

需求与状态 → 表和约束 → API/DTO/校验 → Service/事务 → 数据访问/必要缓存 → 前端页面 → 权限和错误处理 → 测试 → 部署。

可选择“创建、审核、驳回、查询”的业务流程作为小模块，具体业务根据已有行业经验确定。验收不只看 CRUD 数量，还看：

- 前端复杂交互和工程化能力能看见自己的既有经验。
- 权限由服务端验证，而不是仅隐藏按钮。
- 页面、接口、字段与数据库状态能够对应。
- 正常、非法输入、权限拒绝和一次失败路径都能验证。
- README 能让另一人启动、演示和复现关键问题。
- 能清楚标出课程复现、自主开发、参考代码与工具辅助的范围。

如果有真实的前端架构、性能优化、复杂业务或协作成果，把它们整理成匿名案例，作为履历主体。不要把学习项目包装成多年的后端生产经历。

## 九、按 2027 年 3 月启动求职准备

- 11 月：整理真实履历，确定目标城市/行业，收集有代表性的社招岗位，区分“前端主导兼后端”和“后端主导兼前端”。本步做调研，不提前正式投递。

- 1 月：开始模拟面试，检查 Java、SQL、项目调用链和前端经验表达。
- 2 月：定稿主要简历与演示材料，演练项目讲解、现场编码和故障定位，整理 3 月目标岗位清单。

## 十、暂不扩大的内容与版本原则

- 新学习主线保留 Java，不同时开启另一门后端语言的完整路线；如果岗位样本明显偏向另一栈，再单独评估。
- 课程已有工程保持配套版本。当前 hmdp 的 Java 8 编译目标、Boot 2.7.4 不因路线评估而自动升级。
- 新工程的版本在实际创建时结合维护状态和兼容表确定，原 mini-commerce 的 Java17/Boot3.5 只是旧路线配置，不直接沿用为新决定。
- 微服务用课程需要的链路练习，不把所有业务提前拆成大量服务；Kubernetes 和复杂运维暂不作统一前置。
- 高级源码、多个 MQ、多个前端框架、完整 AI 平台开发都不自动加入主线。
- AI 业务功能只在目标岗位或主项目确有需求时作为后期可选，并验证服务端接口、权限、超时与错误处理。

## 十一、复盘规则

每周只核对四件事：

1. 能展示什么新业务行为？
2. 哪个功能能脱离教程独立完成？
3. 哪个原理还不能联系到自己的代码？
4. 下周的工作量或岗位目标需要怎样调整？

11 月底若仍难独立完成一个事务接口和页面联调，优先压缩 Cloud/MQ 的专题范围，补齐已有调用链。1 月底若项目主要是照搬课程，2 月优先完成一条可解释的自设计业务，而不是新增更多中间件。3 月的反馈若指向前端架构或交付经验，就增加真实案例准备，保持后端补课范围与实际岗位相关。
